# 每日笑话 · /jokes

一个可分享的 Agent Skill：首次只补齐偏好，日常生成五个主导喜剧结构不同的短笑话，结合联网精选与原创；定时生成与发送按宿主的真实能力接入。仓库名为 `daily-jokes`，技能短标识为 `jokes`，每次仍生成五条。

## 使用

从本仓库的 Releases 下载 `jokes.zip`，解压后将完整的 `jokes/` 文件夹交给支持 Agent Skills 的宿主安装。保留相对目录，不要只复制入口文件。

将 `jokes/` 放入安装宿主支持的 Skill 目录并确认已发现；仓库根目录本身就是 Skill，从源码归档安装时将技能目录名改为 `jokes`，保持两份 references 一同安装。

支持按技能名注册斜杠命令的宿主，安装后使用 `/jokes`。裸命令首次进入偏好设置；已有配置时直接生成。其他 AI 可读取 `SKILL.md`，识别 `/jokes` 文本并执行同一流程。

Codex 官方明确支持 `$jokes` 或 `/skills` 选择技能；Skill 中的触发文本不会自行注册一个新的原生 `/jokes` 命令。Codex 用户可将下面示例的前缀换成 `$jokes`。复制指令也不会增加搜索、存储或推送工具。[调用方式依据](https://learn.chatgpt.com/docs/build-skills)

所有请求示例均为虚构、去标识化数据：

```text
/jokes

/jokes 设置，先不生成。

/jokes 别问，直接来一组。

/jokes 来五个生活和科技笑话，温和，避开疾病，不加入自嘲。

/jokes 我带了空购物袋去买菜，这件事仅本次可温和调侃，不保存。现在来一组。
```

若用户只要求设置，Skill 不附赠笑话。正常生成只输出编号 1—5 的笑话，网络素材保留对应的必要来源引用。缺少搜索能力时会说明实际降级情况。

## 核心规则

- 区分题材、呈现形式和主导喜剧结构；本组五种不同机制是硬要求，七天轮换是软目标。
- 查重比较目标、行动、误导预期和揭底关系，区分核心包袱复用、同一母题过密与仅题材相同。
- 自嘲默认关闭，只使用明确授权的具体经历；不自动翻阅私事。一次性使用、未来使用、保存和对外发送分别判断。
- 定时需要真实执行与送达工具、明确时区及用户订阅授权。保存发送时间不代表任务已经创建。
- 只把实际展示或发送的内容记录为已送达，按授权保留最小七天查重信息；不把草稿或失败操作记为成功。
- 每位用户的数据与设置独立，Skill 包不包含任何人的真实偏好、经历或历史记录。

## 验证范围

已检查 YAML frontmatter、相对引用、18 个结构 ID、32 项验收规格的必要字段，以及封装文件一致性。完成四个流程场景和五项语义判断的独立模拟；首次设置漏问自嘲选择的问题已修正并复测。

`tests/acceptance.md` 是验收规格，不能将其等同于 32 项全部运行通过。真实联网、定时推送、持久化、跨日联调及原生斜杠菜单注册需在安装宿主中验证；笑话是否好笑仍需要人工和用户反馈判断。
