# 每则独立漫画

在用户选择漫画／图文输出、将指定笑话转漫画或修改已有漫画时读取。本文件定义制作与交付规则，不内置生图模型，不假设宿主有任何固定工具名。新笑话的质量、来源、热梗核验仍按 [幽默规则](humor-rules.md)；配置、授权和送达状态按 [首次设置与状态](onboarding-and-state.md)。

## 输入与数量

- 新生成一组时，先按入口选好短篇，再按用户要求的范围制图。明确要求整组漫画时，默认 10 个短篇对应 10 张独立漫画；每张只讲一个节目，不把整组拼成总海报。长稿不自动制图，每日最佳流程仅制作最佳一则，不能擅自扩为十张。
- 指定一则现成笑话、当前对话第 N 则或某组转换时，只处理指定数量，保留核心包袱，不重新抽取一组；已有内容不为满足新组的来源或机制配额而重写。指定转图不要求重新搜索普通笑话；涉及新添的时事事实或未经核验的热度声明时才核实或删去声明。缺失待转正文或指代不明才补问必要内容。
- 当前请求优先于已确认输出偏好。临时“这次画漫画”不自动更改长期设置；配置了漫画后，普通“生成笑话”沿用该方式。只设置不生图，新增 Skill 功能的讨论不等于要求将其中示例当场画出。
- 用户附图时先实际查看。区分只参考风格与明确使用图片主体；前者提炼画法，不能把参考图里的角色、场景与旧包袱复制给每个新笑话。后者提炼主体最清楚的外形／道具特征用于本条，遵守原素材授权，不凭图片猜测真实人物身份或经历。引用已有图片的编辑须使用宿主实际支持的参考机制；只写“参考上图”而未传入不代表工具收到图片。
- 公共 Skill 只保存通用风格描述，不附带个人参考照片、原始对话、临时路径或私人生成图。不要求重新上传一张当前已可访问的图；确实无法读取且主体还原所必需时再说明缺失。

## 默认画法与分镜

**周日彩色报纸连环漫画**：大胆粗黑描边，清楚格框与留白，印刷网点和轻微纸张纹理，明亮的 1980 年代复古黄、橙红、青蓝与薄荷绿；夸张但连续的表情、动作和道具比例。背景简化服务阅读，网点不覆盖文字；角色在本张各格保持服装、外形和关键道具一致。默认 2×2 四格，短笑话可用 2—3 格，确需更多节拍时可到 6 格；不为凑四格重复台词或添加新事件。用户指定其他画法／版式时按其要求。

制图前在内部整理每则的分镜，不默认要求用户审核脚本：

1. 找一个支撑笑点的清晰视觉反差，如规模、数量、动作或表情反差。夸张要从已有故事长出来，不能添加随机物件或改变因果来硬造笑点。
2. 分配“建立场景 → 形成预期 → 推高预期 → 揭底”的必要节拍，按实际机制调整。最有力的一句及关键动作放末格；不要用标题、封面文字或提前出现的表情泄露结尾。
3. 每格给出角色位置、动作、关键道具、说话者和逐字台词。气泡短、自然、字号足够，优先每格一两句；阅读顺序从左到右、从上到下，气泡尾巴指向正确角色。仅保留理解必需的招牌和时间标记，不塞满背景小字。
4. 时间标签只标故事实际发生的时间。前三格按天推进、末格仍在第三天时，可写“同一天”或省略；不能用“第 4 格”冒充“第 4 天”。数量反差用构图、道具和准确的数字／台词共同传达，不强求读者逐个数画面中的物体。
5. 对话和画面合起来应让未读原文字的人看懂；不在图外另加笑点解析补救。依赖声音或文字游戏时设计可读的台词关系，无法成立就报告局限或在新组选稿阶段换一则；用户指定的笑话不能擅自替换。

## 实际生图

先确认当前可用且允许的生图／编辑工具、参考图传入方式及图像返回方式，按实际 schema 调用，不固定模型或参数。只有搜索图片、HTML 预览或文字能力不等于生图能力。宿主已提供适用的生图 Skill 时遵守其调用方式，不要求安装额外插件才能完成已有能力可做的工作。

每则使用独立的制作请求；工具支持一次返回多个独立成品时可批量，但必须保持笑话与图片一一对应，不能让“批量”变成一张拼贴。同一批保持整体画风一致，每则仍有自己的角色／场景。顺序或并行遵守实际工具限制。

提示词使用以下骨架，填入实际内容，不把骨架当成已生成的图片：

```text
成品：仅一则笑话的一张完整连环漫画，不拼入其他故事。
画法：周日彩色报纸漫画，粗黑描边、网点印刷、轻纸纹、明亮 1980 年代复古配色。
主体／参考图用途：已观察到且用户要求保留的特征；或仅参考画风。
版式与阅读顺序：按该笑话需要的分格，清晰格框和留白。
视觉支点：用具体动作／道具规模承接故事反差。
连续性：角色外形、服装、场景与关键道具保持一致。
逐格：画面动作；说话者；需准确渲染的完整短台词；必要时间标记。
末格：准确呈现原包袱，不追加另一句解释或新事件。
文字：简体中文（或用户所选语言），大字、清晰气泡，背景文字最少。
```

## 看图核验与修正

实际返回图片后，使用宿主允许的查看方式逐张检查；只有文件名或成功字符串不足以证明内容正确。核对一则一张、分格顺序、主体连续性、说话者、关键数字、中文可读性、时间连续性、揭底是否只在末格。尤其检查气泡是否串角色、错字是否改变包袱、参考图装饰是否带进无关情节。

发现影响理解的问题时，优先用原生图像编辑工具修正对应图，保留已通过的其他图片。若没有编辑能力，可重新生成该张。默认对同一问题至多两次有针对性的修正，仍有问题则准确报告，不无限重画。不可读的关键台词或错误包袱不能标成合格成品；没有查看能力时说明图片已生成但未能视觉核验，不声称全部检查通过。

## 展示、来源与失败处理

- 漫画模式按笑话顺序原生展示图片，文字模式维持入口规定的数量，图文模式每则正文与对应图相邻。只用必要序号及来源，不另加笑点解析或漫画风格说明。真实产物支持文件交付时给可打开的文件；宿主已有原生图片结果就使用该结果，不把提示词、占位图或无法访问的链接当成漫画。
- 来源放对应图片外的最短必要引用，避免将长 URL 画进气泡。转换用户提供的笑话时可注明“根据用户提供文本改编”，不能把用户写的“经典／网络流传”当作已核验作者或出处；已核验的来源应保留，重画不使旧包袱变原创。
- 无可用生图能力时，简短说明不能在当前宿主生成图片。若原请求也要文字，可交付文字并说明漫画未完成；仅要求漫画时说明缺口，可提供明确标为“分镜／生图提示词”的替代稿，但不得冒充图片或声称漫画已交付。用户明确不接受替代时只报告障碍。
- 部分图片失败时保留已完成结果，按序号报告哪些成功、哪些失败／未核验；重试只补失败部分，不重新生成或重复发送全部成功图片。十张只完成两张不能称整组完成。
- 文字和漫画是同一笑话的两种形式，不在七天历史里重复计算。必要时按条目分别记录文字／图片的生成与实际送达状态；展示前不预写已送达。仅文字送达不能写漫画已送达；参考原有可核验消息补图时，不重新发已有正文。没有历史权限时只在当前上下文维护对应关系，不扩展为长期图片库。
- 定时漫画必须核实后台有生图及图片送达能力；只配置偏好不自动创建任务，已有文字任务也不能因用户改了形式就假称支持漫画发送。
