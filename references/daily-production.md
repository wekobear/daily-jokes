# 从当日选稿到本地成片

本文件是每日生产的主流程。Agent 负责搜索、内容判断和生图；脚本负责视频生成任务、下载与媒体合成。安装 Skill 不会自动获得模型、搜索服务或视频余额。可交互流程图见 [生产流程展示](../docs/workflow.html)。

## 1. 确定范围

沿用用户的受众、题材、禁区、画风、时长与预算。未指定时采用中文、温和生活题材、虚构通用角色、约十五秒竖屏视频，不使用私人经历。时长是叙事目标，不为塞进十五秒截断台词。每次只生产最佳一则，不为所有候选生图和付费生成。

确认搜索、生图、Python 3.11+、Pillow、FFmpeg/ffprobe 和中文字体可用。视频运行器支持 macOS/Linux；Windows 原生环境尚未验证。视频服务 Key 由使用者在本地自行配置，只检查存在性，不显示值。缺密钥不阻塞选稿、图文和分镜，付费阶段保留待执行。

“今天”采用可靠运行日期；它不代表每个笑话必须今天诞生。“每天自动跑”需要另行使用宿主的调度能力及有效的每次预算，本 Skill 不自行创建订阅。

## 2. 收集候选

先读 [幽默规则](humor-rules.md)。围绕具体冲突搜索，例如“误会 雨伞 短笑话”“找钥匙 路灯 故事”，不只搜“爆笑大全”。可使用公版故事、可合规使用的整理页或用户指定来源；热门和排名不是质量证明。

通常收集八至十条候选，不为凑数无限搜索。实际读到完整相关内容后才入选网络候选，保存 URL、页面标题、读取日期与一句改编依据。搜索摘要不完整、出处无法核验或无法合规使用的，舍弃。不要保存网页全文。

可加入核心包袱独立构思的原创或用户明确供稿；换人物、行业或翻译经典包袱仍是改编。原创和用户供稿如实填写来源种类，不虚构 URL。没有可用搜索时说明真实限制，在用户接受范围内用旧来源或原创，不声称刚完成联网检索。

热梗仅在帮助笑点时采用；“近期”须查证实际传播时间，不把旧整理页更新时间当新梗证据。需要长篇背景科普的素材不适合本短视频。

## 3. 分析并选出最佳

为每条概括“角色目标 → 行动 → 观众预期 → 揭底”，按幽默规则识别主导机制，如误导反转、字面理解或逻辑倒置。找不到成立的包袱，就不因名气留下。

先淘汰：因果不通、只有抱怨、需要结尾解释、临时新增规则、触及禁区、不能合规使用或复用核心包袱的内容。遮掉名字、职业、品牌再比较关系，换皮不算新梗。对本批与可读近期选稿查重；历史缺失就注明只查本批，不声称完整七天查重。旧选稿不等于已上传或已发布。

通过后按各项 0—5 分辅助比较：

| 维度 | 权重 | 判断依据 |
| --- | --- | --- |
| 包袱力度 | 30% | 揭底有清楚反差、重释或行动后果 |
| 独立易懂 | 20% | 不需要背景科普，铺垫短且逻辑闭合 |
| 可视化 | 20% | 动作、道具或表情能承担笑点 |
| 制作稳定性 | 15% | 角色和场景少、道具易保持、台词说得完 |
| 相对新鲜感 | 10% | 与本批和可读历史不同，不靠换名字 |
| 受众匹配 | 5% | 符合当前题材、尺度和观看场景 |

总分 = Σ（单项分 ÷ 5 × 权重百分数），满分 100。分数是编辑辅助，不是客观好笑保证或真实观众反馈。选前三名，再判断哪则能在目标时长里保住完整包袱；相近时优先易懂、制作稳定、成本低的一则。不合格项不能用其他高分抵消。

按 [选稿模板](../assets/selection-template.md)保存 `selection.md`：实际搜索和历史覆盖、候选概要及出处、机制、分项评分、淘汰原因、前三名和最终选择理由。仅记录简洁编辑依据，不输出长篇内部推理或私人记录。没有合格候选则报告缺口，不付费制作弱稿凑完成。

## 4. 图文与分镜

保住必要铺垫、预期和结尾揭底，删掉解释与无用称呼。写短正文、不剧透标题与发布说明，保留来源和 AI 生成说明。常用三个节拍：建立场景、形成预期、最后揭底；按实际笑话调整，不机械凑三镜。

建立角色与画风设定：年龄段、头发/胡须、面部特征、服装颜色、体型、关键道具、背景和光线。用具体通用形象描述，不依赖人物名字替代外形。第一镜确定画风，后续镜用实际参考图保持连续。

每镜需要 `id`、秒数、字幕、`image_prompt` 和 `motion_prompt`。前者描述首帧构图，后者描述动作时序、说话者、完整台词和停顿。例如：

> 保持首帧的白胡子老人、米色头巾、棕色长袍和暖色巷道。四秒单镜头：老人抬手指向路灯，用普通话说“因为这里亮。”年轻人愣住，结尾停留片刻。小幅推进，无新增人物、无画内文字、无追加解释。

这是普通虚构角色的形象写法，不是规避内容审核的办法。服务拒绝时保留实际错误，按规则检查内容；不能推断某个人名必定触发拒绝，也不保证删名字就成功。

实际生成独立 9:16 竖图，逐张查看人物、道具、数量与叙事顺序。字幕留给后期，不将漫画拼格图冒充独立首帧。图像生成需使用宿主真实能力，只有提示词不算图文完成。

制作 `graphic-story.md`，按标题、简介、各镜图片及相邻正文、来源排列，复用同一组分镜。文件内用相对图片路径使目录可搬移，聊天展示时按宿主要求用绝对路径。用户还需要单独漫画长图时才按 [漫画制作](comic-production.md)追加；图文阅读稿不是新增付费出图的理由。

## 5. 视频 API 与本地保存

流程不绑定视频供应商。先读 [供应商替换说明](video-provider-contract.md)，选择用户已有或明确指定的服务，核对它的图生视频、时长、音频、计费和任务接口。随包提供 MiniMax 中国区 H3 参考实现：使用它时读 [视频命令流程](video-workflow.md)和 [MiniMax 接入](minimax-api.md)。其他服务需按同一输入输出语义适配，不是只改域名。搜索和生图费用另计。

完整故事通常三个五秒镜头；低成本联调可复用已有图片，只生成一个四秒 H3 768P 镜头。按 2026-09-12 已核验费率，输出分别估算 7.50 元和 2 元，实际账单以服务商为准。试片不是完整故事，不悄悄替代用户要求的全片。H3-Max 480P 的费用较低，但本项目未做真实画质对比。

已有付费授权和预算就执行；缺少预算决定时先给估算并补足该决定，不重复确认普通阶段。先 `estimate` 再 `generate`。不自动加做试片再做全片却漏算试片费用；重生成也需计入已有消费。

用 [story.json 样例](../examples/umbrella/story.json)的格式写入实际材料。先在单独准备目录存放文案和选稿，`init` 要求目标运行目录尚不存在。初始化后把选稿和图文阅读稿复制进运行目录，逐镜 `image` 登记真实图片，然后按完整命令链生成、下载和合成。

已有目录先 `status`，不重新初始化。退出码 `75` 是处理中，至少十秒后查询已有任务；不明提交先核实，失败保留记录。新的文案版本另开目录并计入原预算，不能清空状态盲目重提。

## 6. 检查并交付

媒体检查确认画幅、时长、编码和可解码性；语义检查实际查看动作、字幕、台词、道具连续性与结尾。不能仅因有 AAC 音轨就声称台词正确。无法听音或看视频时注明待检查，保留已完成产物，不伪造 `review` 以生成交接包。

采用随包参考实现时的正常产物结构（其他适配器应交付同类内容，文件名可以不同）：

```text
runs/<date-story>/
├── selection.md          # Agent 生成的候选比较和选稿依据
├── graphic-story.md      # 图文阅读稿，复用 images 中的分镜
├── story.json            # 正文、出处、形象与镜头提示词
├── images/               # 独立分镜图片
├── videos/               # 下载的第三方视频镜头
├── output/
│   ├── final.mp4
│   ├── final.srt
│   └── cover.jpg
├── state.json            # 私有续跑状态，不分享
└── upload-package.zip    # 视频、封面、字幕、文案与待上传清单
```

图文稿与选稿由 Agent 写入，`pipeline.py` 不会自动搜索或创建这两份文档。交接包只包含内容文件，不包含 Key、Cookie 和完整任务状态；用户写入正文或字幕的私人信息仍需在分享前检查。

最终提供图文、成片和交接包链接，注明“已保存本地，未上传、未发布”，列出实际验证范围与未完成项。用户自行选择平台和手动上传，本流程不需要平台密码或 Cookie。

分享 Skill 使用 `scripts/package_skill.py` 另行打包通用代码与流程；不要分享整个运行区。流程图由 [Archify](https://github.com/tt-a1i/archify) 生成，感谢该 MIT 开源项目，详见 [第三方致谢](../THIRD_PARTY_NOTICES.md)。
