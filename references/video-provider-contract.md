# 更换视频服务，保留内容生产流程

本 Skill 的通用部分是：收集 → 选稿 → 图文分镜 → 视频生成 → 下载与检查 → 本地交付。视频供应商只是其中一个环节。此文定义替换时要保留的输入、输出和行为，不代表本版本已实现所有供应商插件。

## 不变与变化

| 保留的通用内容 | 更换服务时重新适配 |
| --- | --- |
| 候选分析、来源、最佳笑话和正文 | 官方认证方式、Key 字段及服务地址 |
| 角色设定、独立首帧、动作和台词 | 模型名称、图生视频字段和图片上传方式 |
| 镜头 ID、顺序与目标画幅 | 允许时长、分辨率、画幅和参考图限制 |
| 总预算与已发生费用 | 该服务的单价、计费单位、币种和失败计费 |
| 下载后检查、字幕、封面、本地交付 | 异步状态、查询间隔、下载链接及失效时间 |
| 同一任务续跑，不盲目重提 | 幂等键、超时核对方法和服务错误处理 |

先查服务的官方 API 文档，确认它确实支持需要的图生视频、声音和时长。名字相近或接口标成 OpenAI-compatible，不等于视频任务协议相同。

## 输入语义

每镜只发送必要材料：稳定的镜头 ID、首帧文件、运动提示词、目标秒数、画幅、声音要求。提示词包含主体动作、镜头变化、说话者、逐字台词及停顿。角色外形和画风由同组图片保持，不把整个会话或本机路径列表发给服务。

内容层字段可沿用 `story.json` 的 `title`、`source`、`script`、`style`、`shots`。`video` 中的模型设置属于供应商层；当前 `pipeline.py` 的校验和费率表只识别 MiniMax，不把其他供应商名称塞进去冒充兼容。

如果新服务不支持原生配音，必须提前明确使用另一个 TTS 或本地配音，并在合成时对齐，不能以静音轨称为台词已生成。如果时长档位不同，按新档位改编节奏、重新估算，不能直接沿用旧服务的四秒最低档位。

## 任务与输出语义

适配器通常需要估算、提交、查询、下载四项操作；这些是接口职责，不是本项目已经提供的统一插件命令。把供应商自己的状态映射为待处理、成功、失败、取消或提交不明，保留真实任务标识与服务归属，不能跨服务复用任务 ID。

成功后的交接数据至少包含：镜头 ID、真实本地 MP4 路径、文件指纹、实际时长和尺寸、是否有音轨、所用供应商和模型。任务标识、原始服务响应及签名下载地址留在私有运行状态中，不进入公共样例或安装包。

超时或返回不明不能自动当作未提交；先通过服务可用的查询／幂等机制核对。下载失败应查询原任务取得有效地址后重下，不重新付费生成。失败后的新任务也属于预算，不用新建目录隐去旧费用。

## 如何接到本地成片

有新服务时，Agent 按用户指定的官方文档实现并测试该服务适配，再将生成的视频交给通用媒体处理层。现有 `scripts/media.py` 的 `render` 能处理本地镜头、首帧和字幕，但它是 Python 内部函数，不是自动识别任意供应商的命令。

当前 `pipeline.py generate/assemble/upload-package` 仍受 MiniMax 输入校验、任务状态和文件指纹约束。不能把别处下载的视频手动改成 `downloaded`、伪造 MiniMax 任务或 `review` 来“接通”。需要新入口时，正常编写适配和导入逻辑，保留真实供应商的证据。

## 完成标准

先做不收费的参数、错误、状态和预算测试，再在用户授权的预算内完成一条最小真实视频任务。核对提交、查询、下载、播放、完整台词与本地合成。离线模拟通过不等于新视频服务已真实跑通；没有 Key 时交付已实现代码和剩余验证项，不虚报。

本版本已附带并实测的是 [MiniMax 参考接入](minimax-api.md)及其四秒 [H3 案例](../examples/h3-trial/README.md)。其他服务可沿用上述流程接入，但本版本没有其他现成适配器，也没有统一的 `--provider` 开关。
